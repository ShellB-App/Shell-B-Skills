# Shell:B Skills

[![Validate](https://github.com/ShellB-App/Shell-B-Skills/actions/workflows/validate.yml/badge.svg)](https://github.com/ShellB-App/Shell-B-Skills/actions/workflows/validate.yml) [![MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Community skills for [Shell:B](https://github.com/ShellB-App/Shell-B), the local-first AI workspace.
Part of the family with [Shell-B-Themes](https://github.com/ShellB-App/Shell-B-Themes), [Shell-B-Screensavers](https://github.com/ShellB-App/Shell-B-Screensavers) and [Shell-B-Agents](https://github.com/ShellB-App/Shell-B-Agents).

A skill is a playbook an agent loads on demand: a `SKILL.md` with YAML front matter (`name`, `description`) and
Markdown instructions, plus optional scripts, templates and references in the same folder. The format is Claude's
Agent Skills, so skills written for Claude Code or claude.ai work in Shell:B too, and the ones here work there.
Agents see each enabled skill's name and description in their system prompt and load the full text with `use_skill`
when a request matches.

## Install one

In Shell:B open **Tools & Connectors → Community** (the Community Hub). This repository is one of its sources, so its
skills are listed; **Install** copies one into your library, switched off until you have read it and turned it on in
**Tools & Connectors → Skills**. Updates show in the Hub when a skill here changes.

## Write one

```
skills/<name>/
  SKILL.md          front matter + the playbook
  references/       optional: long reference material the playbook points to
  scripts/          optional: helpers an agent can run in its sandbox (read-only under /skills/<name>/)
  template/         optional: files to start from
```

Front matter:

```yaml
---
name: shellb-theme-design          # = the folder name: lowercase letters, digits, dashes
description: >-                    # what it does AND when to use it; this is what triggers the skill
  Design a custom Shell:B interface theme with the design_theme tool when the user asks for a new look …
author: Your name
authorUrl: https://github.com/you  # optional
license: MIT                       # an SPDX id
version: "1.0"
tags: [shell-b, theme]
---
```

What makes a skill good:

- The **description** decides whether an agent reaches for it. Say the situation ("when the user asks for …"), not
  just the topic.
- The **body** is a playbook: steps in order, decisions with the rule for each, the tools to call by name, what to
  check before saying it's done. Move long reference material to `references/` and point to it.
- Name Shell:B's tools where they matter (`design_theme`, `project_save_file`, `run_code`, `create_artifact` …), and
  say what to do when a tool isn't there. Skills written for other assistants are welcome; note their origin.
- No credentials, no calls to private services, nothing destructive.

Then check it:

```bash
python3 -I scripts/validate.py
```

## Credit

Every skill names its author in the front matter, linked when `authorUrl` is given; the name shows in the table
above and in `index.json`, and the git history keeps the pull request under your account. Ported skills credit the
original author in `credits` or in the body.
